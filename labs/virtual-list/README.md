# Virtual List

一个可以复现测量过程的动态列表实验：用**同一份固定文本、同一套行结构和同一个视口**，比较普通全量 DOM 与虚拟列表的初始挂载成本。保留 100,000 条不定高数据、节点池调试和滚动探索。

这不是一个通用虚拟列表库，也不预填 FPS、内存或加速倍数。

## 运行

在仓库根目录，使用 Node.js 24+ 和 pnpm 11.25.0：

```sh
pnpm install --frozen-lockfile
pnpm dev:list
```

发布构建与本地预览：

```sh
pnpm --filter virtual-list-lab build
pnpm --filter virtual-list-lab preview --host 127.0.0.1
```

打开 Vite 输出的地址。测量前建议使用生产预览，减少开发服务器与热更新的干扰。三个实验都可独立运行，不需要 API key 或后端。

## 亲手对照

1. 固定浏览器版本、窗口大小、浏览器缩放与设备电源模式。关闭其他重负载页面和性能录制；不需要为本实验开 CPU throttling。
2. 选择 **500 / 2,000 / 5,000 条**。先切换“普通全量 DOM”和“虚拟列表”，观察实际行节点数。两者都显示相同的记录和文本；虚拟列表的隐藏池槽位也计入行节点数。
3. 点“运行对照”。程序关闭调试透视，从列表顶部开始，各预热一次，然后按“普通/虚拟、虚拟/普通、普通/虚拟”运行三轮。预热不入结果；每次挂载前销毁旧列表，并等待两个帧回调。
4. 查看中位数与最小–最大范围，再展开全部六次原始记录。不要只挑最快的一轮。
5. 导出 JSON。重复整个实验，保留所有文件，并另行记录设备型号、CPU、系统电源模式及屏幕刷新率。浏览器只能提供逻辑处理器数，不能据此推断 CPU 型号。
6. 切换到 **100,000 条 · 仅虚拟探索**，滚动、改变窗口大小、打开调试透视，观察槽位复用和行高修正。这个模式不运行普通全量 DOM，避免一次创建十万条完整行节点。

5,000 条在低性能设备上仍可能短暂停顿。“停止”在同步任务返回后才可响应，无法抢占正在执行的 JavaScript。改变窗口大小或切到后台会取消当前实验，不导出不完整记录。

## 指标的准确含义

| 指标 / JSON 字段             | 如何测量                                                                           | 不代表什么                                             |
| ---------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 同步挂载 `mountMs`           | `performance.now()` 包围渲染器构造和 DOM 插入，含期间触发的样式/布局与遥测文字更新 | 不只是纯 JS 运算，也不是整个页面加载时间               |
| 布局读取 `layoutReadMs`      | 挂载后，单独计时一次 `viewport.scrollHeight` 读取，含它触发的待处理布局            | 不是页面全部布局成本；虚拟列表构造可能已经读取布局     |
| 至第二个 rAF `secondFrameMs` | 从挂载开始到第二个 `requestAnimationFrame` 回调的经过时间                          | 不是绘制完成、稳定帧率或所有行高都已测量               |
| 行节点 `rowNodes`            | 第二个回调后，列表内所有 `.list-item` 数量，含隐藏池节点                           | 不等于浏览器全部 DOM 节点或内存占用                    |
| 后代元素 `descendantNodes`   | 同时读取 `content-box` 内所有元素后代的数量                                        | 不含容器、占位层及页面其他区域                         |
| 内容高度 `scrollHeight`      | 同步布局读取时得到的滚动高度                                                       | 虚拟列表未展示区域仍使用估计高度，不要求与普通列表相等 |

两种方式在计时前共享已生成的数据数组；数据生成、旧列表销毁、结果表构造和导出不在挂载计时内。普通列表一次建立全部行，虚拟列表建立位置数组和可见区节点；它们完成的工作不同。对照用于看清这种取舍，不得将结果泛化为所有场景的“加速倍数”。

`requestAnimationFrame` 等待、操作系统调度、浏览器计时精度与 GC 都会影响结果。本实验没有测量滚动性能、内存、GC、功耗或无障碍完整性。三轮只是可重复的小样本，不能替代正式性能分析。若测量滚动，另用浏览器 Performance 面板记录固定手势或滚动序列，并单独保存结果。

## 固定数据与导出

已有一份[实际生产预览测量及原始数据](measurements/README.md)，只描述当次环境，供复现格式参考。

`src/dataset.ts` 定义 `mixed-text-v1`：记录 id 从 0 递增，标题按每千条分组，五种固定文本通过 `(id * 17 + 7) % 5` 选择。相同数据量每次完全一致；小数据集是大数据集的前缀。没有 `Math.random()`，没有网络数据或定时更新。

JSON 包含：

- 数据版本、条数和文本选择规则。
- 浏览器 user agent、语言、逻辑处理器数、DPR、窗口及列表视口尺寸。
- 开发/生产构建模式；若构建时设置了 `VITE_SOURCE_REVISION`，同时记录该版本标识，否则为 `null`。保存正式对照时，请一起记录 `git rev-parse HEAD` 的输出。
- 计时定义、预热次数、轮次顺序、估计行高、缓冲行数。
- 未舍入的原始六次样本，以及每种方式的中位数、最小值和最大值。
- UTC 生成时间；界面显示本地时间。

改变数据量后，旧结果保留自己的数据量和环境标签；重新测量会替换它。结果仅存在当前页面，导出下载由用户主动点击，不上传。

## 源码导读

| 文件                           | 看什么                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------- |
| `src/dataset.ts`               | 固定数据与可对照规模，10 万条只进入探索模式                                   |
| `src/row.ts`                   | 两种渲染方式共用的行结构与文本填充；调试角标在测量中隐藏                      |
| `src/main.ts`                  | 全量 DOM 的 DocumentFragment 插入、模式切换、预热和测量流程、取消与 JSON 导出 |
| `src/benchmark.ts`             | 交替轮次、原始样本汇总、可取消的帧回调等待                                    |
| `src/virtualList.ts`           | 位置缓存、二分查找、DOM 池、ResizeObserver 修正与生命周期                     |
| `src/style.css`                | 同一套行样式；普通模式使用正常文档流，虚拟模式使用绝对定位                    |
| `tests/virtual-list*.test.mjs` | 行高/视口/销毁边界、固定数据规模、汇总和中断处理                              |

从 `VirtualList.render()` 开始：二分找到起始项，扩展缓冲范围，再把该范围映射到复用槽位。`handleResize()` 收到真实行高，一批观察结果只重建一次受影响的位置后缀；如果视口上方高度变化，则保留当前行内偏移。节点池在视口增大时扩展，并保留历史最大容量。`destroy()` 清理监听、观察器、排队帧和实例节点。

## 复杂度与使用边界

查找起点为 O(log N)，高度变化后的数组后缀修正最坏仍为 O(N)。一次观察回调含 K 条变化时，当前实现约为 O(K + N)。节点复用减少创建，不等于零内存分配或零 GC。

没有通用渲染器、数据增删 API、完整无障碍列表语义或无限滚动数据源。实际产品还需验证焦点管理、图片异步尺寸、浏览器查找、滚动锚定和目标设备。

## 检查

```sh
pnpm check
```

执行格式、三个实验的 TypeScript 检查、回归测试和生产构建。虚拟列表单元测试使用受控 DOM/ResizeObserver 替身，只验证状态与生命周期；它不模拟真实浏览器布局。数据/汇总测试不证明性能，真实时间只在用户当前浏览器运行后产生。
