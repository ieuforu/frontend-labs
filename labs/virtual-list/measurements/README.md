# 一次实际浏览器对照记录

[原始 JSON](2026-11-02-iab-2000.json) 来自 2026-11-02 10:35（Asia/Shanghai）的本地生产预览，
源码版本 `e7e683a`。通过 ChatGPT 内置浏览器操作页面的“运行对照”和“导出 JSON”获得，未使用个人 Chrome。

窗口 1280 × 720 CSS px，列表视口 918 × 520 CSS px，DPR 2；浏览器报告 12 个逻辑处理器。
CPU 型号、电源模式和屏幕刷新率未记录，不根据 user agent 的兼容字符串推断实际系统版本。
完整浏览器标识、协议和六次原始样本都在 JSON 中。

同一份 `mixed-text-v1` 数据，共 2,000 条。两种方式各预热一次，之后交替测三轮：

| 指标（中位数）    | 普通全量 DOM | 虚拟列表 |
| ----------------- | -----------: | -------: |
| 同步挂载          |     11.10 ms |  0.60 ms |
| 挂载后布局读取    |     43.40 ms |  0.60 ms |
| 至第二个 rAF 回调 |     74.60 ms | 16.80 ms |
| 行节点数范围      |  2,000–2,000 |    20–20 |

这个例子体现了“完整建立所有行”和“先建立位置缓存与可见行”的工作量差异。
虚拟列表对屏幕外行高仍使用估计，后续滚动与尺寸变化还有成本。
这里没有测量内存、滚动 FPS、GC 或用户交互延迟，不能由节点数直接推导内存节省，也不能把第二个 rAF 当作绘制完成。

这是一次环境特定的小样本，目的在于保留可检查的测量证据，**不是跨设备性能承诺**。
复测时使用 [实验协议](../README.md#亲手对照)，保留所有原始轮次，再比较波动和结果。
